## 3. 五类缺陷的共同根因与修复

共同问题是把几何位置或词语共同出现当作科研角色证明，以及提取器和校验器共享不充分的假设。新代码使用受限的正向合同；无法解释时弃权，不猜测其他字段。

| 缺陷 | 修复前实际复现 | 最终行为与代码位置 |
|---|---|---|
| P1 评测范围冒充数据集轴 | 泛指两个数据集的表注允许优化器等列被解释为dataset | `table_roles.dataset_contract` 要求每列正向身份，检查明确关联正文；仅有数据集数量不够 |
| P1 分离正文的指标/单位例外被忽略 | 表注单一accuracy，独立文本块的列例外未阻止整表套用 | `table_contexts/_context_consistent` 纳入同论文、同页、同表号及同物理文本块后缀；未消费的列限定或冲突拒绝 |
| P1 增益/比值当绝对测量 | Gain over、Ratio(B/A)等进入accuracy结果 | `method_identity` 识别完整派生关系与现有行之间算术关系，另覆盖Mean of、Average across、Ratio B/A |
| P2 父表浮点微差重复 | 同单元格、不同来源ID或父框微差产生重复结果 | `same_physical_cell` 比较论文/页/表注/行列/原始单元格与真实单元格框；最大0.02pt且IoU≥0.99；不按科学字段全局合并 |
| P2 合法Delta被删除 | 有模型定义仍当差值 | 对统计同名行要求明确模型身份原文；合法Delta、GainNet、Ratio Model、Change Transformer等保留 |

最初新增的32项合成测试在修复前为26失败、6通过，日志已冻结。后续主动反例与真实响应回归扩充为69项。

这些测试包含实际合成PDF解析及成功恢复的表格，再检查提取、字段证据及上传链路；没有用“表格根本没有识别”冒充上述五类缺陷被拦截。

## 4. 真实调用发现的额外问题

### 4.1 GCN上下文缺失与单位来源

早期验收脚本仅传目标单元格自身的证据，遗漏同一表格其他两列的数据集定义。严格合同要求整个矩形轴具有依据，因此拒绝是合理的。此为验收上下文缺陷，不能归咎于模型。

补齐同一表格所有已验证单元格需要的原始角色证据后，冻结GCN响应可离线通过。另确认两个通用问题：`classification accuracy`应与accuracy采用同一规范名称；明确引用当前表号的正文可直接声明全表“reported numbers denote classification accuracy in percent”。现仅在整个表格角色/冲突合同通过后，允许该闭合声明支持单位，不能借用其他表、其他论文或训练标签比例。

仅补齐上下文的离线成功不算真实模型新成功；随后第13次真实请求才完成定向GCN验收。

### 4.2 GAT字段复制及错误划分

初期模型把数据集引文指向不含该名称的结果行，或使用R定位编号冒充S来源ID，均被拒绝。第15次响应虽然核心测量元组正确，却额外把Cora填为split，旧校验曾接受：这是本轮确认的错误接受，不能掩盖。

现在数据集列名不能凭同一列头或附加表注同时证明训练/验证/测试划分；错误字段仍由模型自行纠正或置空，程序不静默修复输出。冻结第15次响应在最终版本被拒绝。

`_result_context_payload` 增加真实来源ID与连续原文的字段引用辅助；所有字段仍重新核验。仅原文行名有明确作者标记（ours/this paper/this work/this study）时，对提示中的单元格顺序做稳定优先排序，保留所有基线、原文、ID和规则结果顺序，不宣称其他行属于作者原创。

`_screen_extraction` 将失败字段及原因代码反馈给唯一一次纠错，排除通过/未提供字段；不增加重试次数。

### 4.3 引文共同出现不足以核验行列关系

错数据集命题的真实模型两次错误给出supported，解释甚至同时列出相反事实。初次最终弃权主要依赖缺少指标方向，不能宣称已经识别错列。

新合成复现表明，补齐真实表头、整表和表注后，旧校验仍会接受错行、错列或误差项作为主结果：6项对照中3失败、3通过。

`research_guard._table_binding_gap` 现在仅对现有坐标数据集矩形表增加否决：所选引用必须包含同一来源的完整表头和对应结果行，命题方法行、数据集列及主数值须唯一绑定。不同来源的片段不能拼成一张表；不能借另一单元格、误差项或时间项证明主结果。对支持检查主数值，对反驳不要求错误命题的数值等于原值。缺失或多义时只降为insufficient，不生成相反事实。

该检查不证明数据集角色、统计协议或一般语义，不取代独立模型/人工判断。另以合成失败测试确认并修复accuracies复数被误认为缺少accuracy方向的问题，accuracy/error区分仍保留。

## 8. 提交前独立自审结论

- 列身份：改为每列正向证明；明确同表正文冲突优先弃权。没有仅凭列数或排除黑名单认定dataset。
- 指标/单位：同表闭合合同及明确全表单位来源；其他论文/表号/训练比例负例仍拒绝。未跳过逐字引用。
- 方法/派生：完整派生表达式不作为绝对准确率，统计同名模型需要定义；不按任意位置关键词删除名称。
- 去重：只在相同论文/页/表注/单元格物理身份下做有界等价，不改历史证据，不合并独立页/表/论文。
- 模型校验：规则与模型仍共享角色合同，不代表两次独立科学证明。新增直接行列否决只用于防止已知错配，不提升模型的语义判断为事实。
- 初始上传、候选、人工审核、快照API及数据库模式未改；未改默认截断/页码约束。
- 来源稳定性：原始ID、文本不重写，S别名仅本批映射；R只定位。提示顺序及规范metric改进可能影响新模型输出/新候选ID，不追溯修改历史ID。

仍有明确限制：

1. 正向英文合同较窄，列特定或难解释的同表正文可能造成漏提取；不保证所有科研表格、跨页/合并/多级表头。
2. 语义模型仍会错归属、解释与标签矛盾、忽略优先级；来源检查是有限否决，不能保证所有错误都可被拦截。
3. 数据集表格核验要求所选引用含明确行/列；方法别称、多对象比较或缺少完整行列时保守弃权，不能视为通用表格推理器。
4. dataset与split同名的模型输出现在保守拒绝，可能需要人工建立真实划分；未为疑似同名设置猜测例外。
5. 两篇开发论文定向模型各成功一次，不是稳定成功率；默认全文/12条/默认元数据补全未作真实端到端验收。
6. 跨论文普遍优越性核验仍有协议/覆盖失败；未制造可比或统计显著性结论。
7. 本轮未操作正式浏览器/8792，也没有新增真实浏览器截图，不能把API验收写成浏览器验收。

本轮确认的五项规则缺陷及新增确定性来源缺陷已被测试拦截，未在已覆盖反例中留下未修复的P1；这不是对所有PDF及模型输出的无P1保证。
