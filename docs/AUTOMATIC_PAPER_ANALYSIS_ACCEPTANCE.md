| 问题 | 修复前证据 | 本轮处理 |

## 3. 修改文件和逻辑

### `backend/app/experiment_validation.py`

新增 `verify_pdf_measurements()`、`machine_measurement_verified()`、`prioritize_measurements()` 及少量内部摘要工具。

机器核验限定为 **method / dataset / metric / value / unit**：

1. 读取原始 PDF 字节，核对上传/入库 SHA256；失败则弃权。
2. 保留既有 `prepare_experiments`、逐字段字面引文和单位归属检查。
3. 仅支持已有 `caption_bounded_dataset_grid`，要求唯一同页表注及每列的正向数据集身份。
4. 继续使用保守的同表指标/单位合同与关联正文冲突检查；不把未知列当数据集，不把派生行当方法。
5. 重新读取 PDF 的原始 words 与支持段落，不仅重新调用原提取器。核对真实表头、方法行、结果单元格、同一行的纵向重合及列中心位置。
6. 检查表框内包含关系、行列不重叠、上下文与表格原文一致。发现同位置的冲突表格表示时弃权。
7. 方法/结果引文必须绑定该行，数据集引文必须绑定该表头，指标引文必须绑定该表注；不能借另一个同数值行的引用。
8. 主值只取完整原始单元格中的主结果；误差项、时间项不能变成第二个结果。注释必须与原文解析一致。
9. 对有非空但未在本核验范围证明的 task/split/sample_size/conditions 保守弃权，不静默删除字段后“通过”。
10. 记录版本、原始 PDF SHA256、输入证据 SHA256、测量及引用摘要、具体检查项、来源 ID、页码、结果框、完整单元格和未核验字段。

`review_required` 没有改成 false，`human_reviewed` 明确为 false。既有人工审核语义保留，新的机器状态只说明测量字段已经过上述检查，不冒充人工审核。

排序只识别原文方法行中的 `(ours)`、`(this paper)`、`(this work)`、`(this study)` 等明确标记，并要求本次机器核验通过。没有论文名、模型名、数据集名、页码或目标数值白名单；未标记的行不被改称论文主方法。排序不重写结果 ID，不丢弃外部基线。

## 4. 独立性和安全能力的准确边界

本轮不是“同一模型再问一次是否正确”，也没有调用模型投票。新增部分直接读取原始 PDF 文字和位置，能拒绝“表格文本、结构化值及引文彼此一致，但与真实 PDF 不符”的合成反例。

**语义角色合同仍与提取器共享；PyMuPDF 文字层也是共同基础。** 因此这不是两套完全独立的科研语义证明，不能排除共同的 PDF 文字层或未支持的语义错误。界面的通过范围仅是原文测量关系，不是科研真实性、可重复性、实验协议一致性或统计显著性认证。

证书绑定当前记录和证据集合；字段/引文改变会使摘要失效，人工修改直接撤销当前证书。候选保存仅换记录 ID，不会导致证书失效。重新解析或证据集合发生变化后，旧证书可能保守失效，不能假定自动继承为有效；本轮验证的是首次完整 PDF 上传与不重新解析的默认规则候选流程。

## 6. 比较的实际结论

目标实验对：数据集 Cora、指标 accuracy、单位 % 一致；主值分别 81.5 与 83.0，方法不同。自动结构化结果没有证明任务、划分及完整实验条件，因此：

- `comparability=insufficient`，`verdict=insufficient`，`delta=null`。
- 显示具体缺失字段及方法/数值差异。
- 不计算受控性能增益、不认定普遍优越、不假称统计显著。
- 比较和报告业务链路可以自动完成；**完整协议对齐没有自动完成**，这部分是明确限制，不能包装成完整科学比较成功。

原始论文可能包含更多协议信息，当前系统尚未自动建立足够严格的逐测量协议归属。本轮没有为了补齐它而猜测条件或混入已有人工记录。
